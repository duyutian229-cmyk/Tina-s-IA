## 一、技术栈定稿

选型原则只有一条：**依赖越少，"跑不起来"的概率越低。**

| 层 | 选型 | 安装成本 | 理由 |
|---|---|---|---|
| 服务端 | Python 3.13 + **Flask** | `pip install flask` | 一个文件就能跑起一个网站 |
| 数据库 | **SQLite**（Python 内置 `sqlite3`） | **0** | 标准库自带，单文件，随作品一起提交 |
| 前端 | **原生 HTML / CSS / JS** | **0** | 不用装 Node、不用打包 |
| 音频播放 | **pygame.mixer** | `pip install pygame` | 服务端循环播放，`play(loops=-1)` 一行搞定 |
| 客户端↔服务端 | **HTTP 轮询** | 0 | 每 3 秒问一次，够用且好调试 |
| 版本管理 | Git（可选但强烈建议） | 已有 | 开发日志的一部分，也是 Criterion D 的证据 |

**总计：2 个 `pip install`，0 个前端工具链。**

### 明确不用的东西（都是陷阱，不是能力问题）

| 不选 | 理由 |
|---|---|
| React / Vue / 任何前端框架 | 学习成本是本项目总时间的数倍，且对评分毫无帮助 |
| Django | 全家桶，90% 的功能用不上，配置成本高 |
| ORM（SQLAlchemy 等） | 会写 SQL 就够了；ORM 反而让算法逻辑变模糊，且**标准 D 要展示 SQL 技巧** |
| WebSocket | 实时性要求只有 3 秒，轮询足够；WebSocket 调试成本高 |
| Docker / 云服务器 / npm / Node | 演示用局域网，全部不需要 |
| 任何"拖拽建站"工具 | **IB 明确规定这类产品不得分**（讲义 §4.3） |

## 二、学习原则："会用即可"的底线在哪里

老师的要求是"不必要真正学懂某门语言，会用即可"。这个方针是对的，但**有一条红线必须划清**：

> IB 官方把"**只用复制代码开发的程序**"列为**不恰当的产品**（不得分/低分）。
> 附录里提交的完整源代码是会被看的。

所以"会用即可"的底线是这三条——**过了就算合格，不必更深入**：

1. **能指出每一行为什么在那里**（不是"书上这么写的"）；
2. **能改一个参数并预测结果**（"把权重从 0.3 改成 0.5，结果会变成……"）；
3. **能不看原代码，写出一个简化版**（比如把打分函数从 5 个标签砍到 2 个标签重写一遍）。

**唯一验收动作**（老师可以直接用来检查）：
> 让 Tina 把打分器的某个权重改掉，然后**口头预测**哪个顾客会得到不同的曲子。答得出来 = 这条技术过关，可以去写下一块。

### 关于使用 AI / 网上示例

- ✅ **可以用**来：解释概念、生成 10 行的最小示例帮她理解、帮她排查报错；
- ❌ **不能**直接粘贴进作品——作品里每一段代码都必须通过上面三条底线；
- 附录里的完整源代码会成为 Criterion D 的直接证据，**注释和可读性从第一天起就要写**（讲义 §4：D 要求"代码有注释、风格一致、可读"）。这件事最后补的代价是现在的 5 倍。

## 三、阶段 0：最小启动包（9/14 – 9/27，2 周，约 8 小时）

**这一阶段的目标不是学习，是把作品的骨架跑通。**

四个独立小实验，每个不超过 2 小时：

| # | 实验 | 内容 | 大约用时 |
|---|---|---|---|
| 1 | **Flask hello** | 一个 `app.py`，浏览器访问返回 "Hello" | 30 分钟 |
| 2 | **SQLite 读写** | 建一张表、插一行、查出来打印 | 1 小时 |
| 3 | **pygame 出声** | 加载一个 mp3 并循环播放，按键停止 | 30 分钟 |
| 4 | **网页提交 → 出声** | 一个 HTML 表单 POST 到 Flask，Flask 播放音频、返回 JSON，页面显示结果 | 2 小时 |

**第 4 个实验就是整个作品的骨架。** 之后 4 个月的所有工作，都是往这个骨架里填内容。

> ⚠️ **第 4 个实验里必须验证的关键设置**：Flask 默认只监听本机，手机访问不到。必须用
> ```python
> app.run(host="0.0.0.0", port=5000)
> ```
> 同时 Windows 防火墙要放行 5000 端口。**这一条没通，后面所有局域网演示都是空谈**，所以务必在第 2 周就验证，别拖到 1 月。

**每个实验都要留档**（截图 + 那几行代码），它们是 Criterion D 的第一批证据。

## 六、三个容易踩的坑（提前知道能省好几天）

1. **`host="0.0.0.0"` + 防火墙**：见 §3。手机打不开页面的第一大原因。
2. **服务端音频格式**：`pygame.mixer` 对 mp3 的支持依赖底层库，**优先用 `.ogg` 格式**最稳；如果 mp3 播放报错，先换成 ogg 再排查。
3. **文件路径用绝对路径或 `os.path`**：从浏览器提交过来的路径是 POSIX 风格，Windows 上要小心；曲库路径统一写在配置文件顶部，不要散落在代码里。
